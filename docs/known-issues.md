# Known Issues

Real-world issues encountered across projects using Muffin. Covers confirmed bugs, architectural limitations, and patterns that were unclear from docs alone. Resolved items are kept for reference.

| # | Area | Issue | Workaround | Status |
|---|------|--------|------------|--------|
| 1 | Event binding | `on-keydown`, `on-focus`, `on-blur`, `on-dblclick` were not in the supported `on-*` attribute list. | Bind imperatively via `addEventListener` in `onConnect`, remove in `onDisconnect`. | Resolved in atom-websdk 3.1.5 |
| 2 | Service — static `this.interface` | `this.interface` is `undefined` in static service methods. Developers expected it to work like a component instance. | Subscribe on a PostOffice socket (`Muffin.WebInterface.websubscribe(address, 'global', label)`) and listen there. See [Service docs](/api/service#subscribing-from-a-service). | Not a bug — expected JS behaviour. Documented. |
| 3 | Child component attribute reactivity | When a parent re-renders and changes an attribute on a child Muffin custom element, the child does not re-render. There is no `observedAttributes` / `attributeChangedCallback` equivalent. | Render dynamic output inline in the parent template (e.g. `LucideIcon.renderIcon(...)`) instead of passing a changing attribute to a child component. The parent reconciler then replaces the output wholesale. See [DOMComponent docs](/api/dom-component#dynamic-attributes-on-child-components). | Architectural limitation — documented. No fix planned. |
| 4 | Store subscriptions not firing | Components declaring `this.stores` in `constructor()` were not auto-re-rendering when `store.set()` was called externally. `_subscribeToStores()` ran inside `super()` before the subclass constructor could assign `this.stores`, so the subscription was never registered. | `store.subscribe(() => this.render())` manually in `onConnect()`. | Resolved in element 0.9.3 / atom-websdk 3.1.6 |
| 5 | `composedScope` after `switchState` | After calling `switchState('loaded')`, children in the new state's markup are not yet mounted in `composedScope` synchronously — the parent's render is queued via `queueMicrotask`. Accessing `composedScope.child` immediately after returns `undefined`. | Use `awaitChildLoad` which resolves deterministically when the child's `connectedCallback` fires: `await this.awaitChildLoad('child')`. Do not use `setTimeout(0)`. | Architectural behaviour — documented in [State Machine guide](/guide/state-machine#composedscope-after-switchstate). `composedScope` itself is unaffected; the timing is a render scheduling concern. |
| 6 | Boolean attribute removal on re-render | Boolean attributes (`disabled`, `readonly`, `checked`) set via a `${}` expression in `markupFunc` are not removed when the condition flips on a subsequent render. The DOM patcher calls `setAttribute` but never `removeAttribute`. | Manage toggling boolean attributes imperatively via `setAttribute`/`removeAttribute` in `postRender` rather than in the template. | Resolved in element 0.9.4 / atom-websdk 3.1.8 |
| 7 | `on-load` — handler fires late for cached resources | For cached images/media, the browser fires the `load` event synchronously during DOM insertion — before `__processRenderedFragEventListeners` attaches the `on-load` handler. The handler is never called. | Attach `addEventListener('load', handler, { once: true })` imperatively after render. Check `el.complete` first and invoke directly if already loaded. | Resolved in element 0.9.4 / atom-websdk 3.1.8 |
| 8 | `getElement` / `getElements` undiscoverable | Scoped DOM query helpers `getElement(selector)` and `getElements(selector)` exist on every component but were not in the public API docs, leading developers to use `_getDomNode().querySelector()` or `document.querySelector()` directly. | Use `this.getElement(selector)` and `this.getElements(selector)`. See [DOM Extensions docs](/api/dom-extensions). `_getDomNode()` is internal and not part of the public API. | Docs gap — resolved. |
| 9 | Multiple instances of same component type mapped to same DOM node | `_processChildCmps()` matched child components by `domElName` only. With multiple instances of the same type (e.g. 10 `<lucide-icon>` components with different `icon` attributes), `find()` always returned the first match — all instances collapsed to the same DOM node and disappeared or corrupted. | Use `childscope` attribute to uniquely name each child component instance. | Resolved in element 0.9.2 / atom-websdk 3.1.0 — `_processChildCmps()` now requires both `domElName` and `childscope` to match; components without `childscope` are skipped and recreated cheaply. |
| 10 | Focused element grafted after view switch | Clicking a button that switches views (e.g. "← Back") left that focused button inside the new view, replacing unrelated content such as another button's label. The reconciler protected any focused element from replacement, not just text fields. | None needed after upgrading. | Resolved in element 0.9.4 / atom-websdk 3.1.8 |
| 11 | Imperatively-set attributes removed on re-render | In 3.1.8, attributes set via `toggleRootAttr` (or by hand) were stripped on the next re-render, e.g. a modal setting `is-open` closed immediately after opening. | Upgrade to 3.1.9. | Resolved in element 0.9.5 / atom-websdk 3.1.9 |
| 12 | Router lost or repeated the address's query | At load the router pushed a rebuilt address: in path style the first query param was dropped (`/?x=1` became `/home`), params were repeated (`&k=1&k=1`), `basePath` was ignored, and values weren't encoded. | Upgrade to 3.2.0; build links with `href()`. | Resolved in element 0.10.0 / atom-websdk 3.2.0 |
| 13 | Replies crossed between requests to one interface | Replies were matched by interface alone: two requests in flight to one interface could each get the other's reply (or the first reply for both), and a reply after a timeout went to the next request. A reply with `result: null` never resolved; each request left two listeners behind; a closed connection left requests waiting for their timeout. | One request in flight per interface (apps queued their own). | Resolved in atom-websdk 3.4.0 with the gateway (rtc:webrequest-handler) sending each request's `ref` back — any number in flight, each its own reply. |
| 14 | Services shared one cache | `Service`'s TTL cache was one map for every service class, so the same key in two services collided. | Prefix keys with the service's name. | Resolved in atom-websdk 3.4.0 — each service class its own cache. |
| 15 | Two sockets when reconnecting | `connect()` called again while connecting (two parts of an app reconnecting at once) opened a second socket; sends failed until the newer one opened, and the older stayed open, delivering events twice. | Await one shared `connect()` promise. | Resolved in atom-websdk 3.4.2 — calls made while connecting share one attempt. |
| 16 | Subscriptions gone after a reconnect | A new socket starts with no subscriptions at the gateway: an app that called `connect()` again after a close kept its routes but got no more events, unless it subscribed again itself. Each app wrote its own reconnect and re-subscription. | Subscribe again after each reconnect. | Resolved in atom-websdk 3.5.0 — `reconnect: true` reopens the connection and makes its subscriptions again, then dispatches `resumed`. |
| 17 | One unsubscribe ended everyone's | `webunsubscribe(address)` dropped every route of the address and stopped it at the gateway, though another part of the app still listened. | Do not unsubscribe a shared subscription. | Resolved in atom-websdk 3.5.0 — `webunsubscribe(address, { socketName, label })` ends one route; the gateway is told when it was the last. |
| 18 | `connect()` could wait forever | A socket that closed before opening without an error first left `connect()` unsettled. | — | Resolved in atom-websdk 3.5.0 — it rejects. |
| 19 | Another SDK took a connection over | `WebRequestSdk` used `window.Muffin` whenever it opened a socket or routed an event; a page that loaded another SDK afterwards (a widget's 2.x) replaced it, and the connection's sockets and events went to that one's PostOffice. | Load no other SDK after the app's. | Resolved in atom-websdk 3.5.0 — a connection keeps the Muffin it was made in. |
